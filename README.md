# Katic Designs: Website

Marketing site for Katic Designs (architecture, interiors and construction; Kochi and Dubai).
It rebuilds the original single-file HTML site in **Next.js (App Router) · React 19 · TypeScript (strict) · Tailwind CSS v4**, with pixel-perfect parity. A Laravel API will later replace the static content layer.

- **Plan and phases:** [docs/MIGRATION_PLAN.md](docs/MIGRATION_PLAN.md)
- **Inherited and new defects:** [docs/KNOWN_ISSUES.md](docs/KNOWN_ISSUES.md)
- **Decision log:** [docs/DECISIONS.md](docs/DECISIONS.md)
- **Source audit (per-page specs, animation catalogue):** [docs/analysis/](docs/analysis)

## Requirements

- Node **22** (see `.nvmrc`; ≥ 22.12)
- pnpm via Corepack: run `corepack enable` once. The pnpm version is pinned in `package.json`.

## Getting started

```bash
corepack enable
pnpm install          # also installs the git hooks (husky)
pnpm dev              # http://localhost:3000
```

## Scripts

| Script                                                         | What it does                                                                                        |
| -------------------------------------------------------------- | --------------------------------------------------------------------------------------------------- |
| `pnpm dev` / `build` / `start`                                 | Next.js dev server / production build / serve the build                                             |
| `pnpm check`                                                   | typecheck + lint + format check + unit tests (run before opening a PR)                              |
| `pnpm typecheck`                                               | Generate route types, then `tsc --noEmit`                                                           |
| `pnpm lint` / `lint:fix`                                       | ESLint (strict type-checked, jsx-a11y strict, import sorting), zero warnings allowed                |
| `pnpm format` / `format:check`                                 | Prettier (+ Tailwind class sorting)                                                                 |
| `pnpm test` / `test:watch`                                     | Vitest unit tests                                                                                   |
| `pnpm test:e2e`                                                | Playwright e2e against a production build (builds and starts it locally)                            |
| `pnpm assets:sync`                                             | Copy images and videos from `reference/` under semantic names and regenerate `src/content/media.ts` |
| `pnpm ref:extract [--download]`                                | Rebuild `reference/original/` (stripped HTML + extracted assets) from the original site             |
| `pnpm ref:serve`                                               | Serve the original site at http://localhost:4310 for side-by-side comparison                        |
| `pnpm ref:capture [--routes a,b] [--viewports desktop,mobile]` | Capture the per-section parity baseline from the original site into `reference/baseline/`           |

## Design system

- Tokens live in `src/app/globals.css` (Tailwind v4 `@theme`). The palette, type scale and breakpoints are restricted to the design system, and **1 spacing unit = 1px**.
- Primitives live in `src/components/ui` (`Section`, `Container`, `Kicker`, `SectionTitle`, `HeroTitle`, `Lead`, `Body`, `Button`/`ButtonLink`, `MoreLink`, …) and `src/components/icons`.
- Sections set `tone="light" | "dark"`; children use tone-aware colours (`text-fg`, `text-fg-muted`, `text-kicker`, `bg-surface`).
- Desktop (≥1100px) is a fixed 1440px canvas scaled with CSS `zoom` (`src/lib/zoom.ts`).
- Browse every primitive at **http://localhost:3000/styleguide** (dev only; production builds need `ENABLE_STYLEGUIDE=1`).
- `tests/e2e/design-system.spec.ts` checks the primitives' rendered styles against values measured on the original site. To run it against a dev server you already have open: `E2E_BASE_URL=http://localhost:3000 pnpm test:e2e`.

## Reference material (`reference/`, git-ignored)

The original site and everything derived from it stay out of git because they are large and regenerable:

```bash
pnpm ref:extract --download   # original HTML → reference/original/ (stripped copy + assets)
pnpm ref:capture              # parity baseline → reference/baseline/<viewport>/<route>/
```

`reference/screenshots/` holds the browser QA captures from the audit (see `docs/analysis/05-visual-qa.md`). It can only be regenerated by re-running that audit.

## Project structure

```
src/
  app/             routes (App Router)
  assets/images/   site images, semantic names (generated by `pnpm assets:sync`)
  content/         typed content; media.ts is generated
  lib/             domain logic, data repositories, utilities
public/video/      hero videos
scripts/           asset and reference tooling (+ unit tests)
tests/e2e/         Playwright e2e
tests/visual/      original-site server, baseline capture, route/viewport definitions
docs/              plan, decisions, known issues, analysis
```

The full target structure is in the [migration plan §4](docs/MIGRATION_PLAN.md#4-project-structure).

## Workflow

- `main` only receives merges from `dev` through pull requests. Never commit to `main` directly.
- Work happens on `dev` (or short-lived branches off `dev`).
- Commits follow [Conventional Commits](https://www.conventionalcommits.org/); the `commit-msg` hook enforces this. `pre-commit` runs ESLint and Prettier on staged files.
- Fixes for an inherited defect reference its ID, e.g. `fix(works): reflow filtered grid (KI-L05)`, and update its status in `docs/KNOWN_ISSUES.md`.
- CI (`.github/workflows/ci.yml`) runs typecheck, lint, format check, unit tests, build and e2e on pushes to `dev` and `main` and on PRs.
