# E — Visual QA / layout-bug hunt (single-file hash-routed site)

Source tested: `scratchpad/site/index.html` (16 MB, served locally via `python3 -m http.server 8765`, server stopped after the run).
Tooling: Playwright 1.56.1 / Chromium 1194. Scripts in `reference/qa-scripts/`:

| script | purpose |
|---|---|
| `audit.js <w> <h> [routes]` | Loads each route fresh, scrolls in 400 px steps (90 ms) to trigger IntersectionObserver lazy images and reveals, then returns to the top. Takes a full-page PNG plus a viewport PNG and runs DOM checks (overflow offenders, broken/unloaded/distorted images, text overflow and clipping, fixed header over the H1, small inputs and tap targets). Deep-link routes also get an anchor/header-overlap check and an anchor viewport shot. Uses `reducedMotion: 'reduce'`. |
| `interact.js <w> <h>` (env `STEPS=` to subset) | Desktop dropdowns / mobile menu + submenus, works filter, blog category deep links, project lightbox, divisions carousel, home “Selected Works” tabs, renovation before/after, every FAQ accordion (clip check), contact form + pop-up form empty/invalid submit. |
| `motion.js` | Home with motion ON at all 4 widths: viewport frames every 0.75 vh (wheel-scrolled) and a full-page shot. |
| `overlap.js <w> <h>` | Finds pairs of visible text nodes whose boxes intersect on every route. Has false positives: it ignores `overflow:hidden` clipping, so collapsed FAQ answers and hidden division slides show up. |
| `montage.js`, `sheet.js`, `crop.js` | Build review montages and contact sheets from the PNGs. |
| raw results | `results-<w>.json`, `interact-<w>.json`, `overlap-<w>.json`, `motion.json` |

Widths: 1440×900, 1024×768, 768×1024 (isMobile/touch), 390×844 (isMobile/touch).
Routes: the 24 listed pages, `#article/designing-for-kerala-monsoon`, `#works/works-list/residential` and `#blog/blog-list/architecture`. All 27 routes loaded at all 4 widths (108/108 passed).

**Important for the "pixel-perfect target":** the site applies `zoom: var(--z)` to `.page` at ≥1100 px (`--z = clientWidth/1440`). So 1440 is the 1:1 design, and anything between 1100 and 1439 is the 1440 layout scaled down. At **≥1100 px with reduced motion** two pinned sections render differently (see bugs #1 and #2). For those sections at 1440, use the motion-on frames in `shots/motion/1440/` as the reference, not the reduced-motion full-page PNG.

## 2. Console / page errors

- **No `pageerror` (uncaught JS exceptions) and no `console.error` from script on any of the 27 routes × 4 widths, or during any interaction.**
- With motion ON (no reduced motion) the home hero requests `katic-banner-desktop.mp4` / `katic-banner-mobile.mp4` over HTTP and gets **404** locally (seen 11× / 4× in the server log). This is expected: the code tries the external file first (`v.dataset[k]`) and falls back to the embedded base64 video (`#kv-desktop` / `#kv-mobile`) on `error` or after 2.5 s. The Next.js rebuild must ship these two mp4s (plus posters `poster_desktop`/`poster_mobile`). With reduced motion the video is paused, nothing is requested, and the poster shows.
- `favicon` / other assets: no other 4xx/5xx responses.
